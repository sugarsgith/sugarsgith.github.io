# 保守手順

サイトの HTML を変えない確認と、機種を足すとき・確率表を直すときの手順です。公開は GitHub Pages が `main` のルートを配信します（Pages のソースはブランチ `main`、パス `/`、ビルド種別 legacy）。

## ローカルで開く

リポジトリのルートで静的サーバーを立てます。パスが `/sw.js` や `/topbar.js` のようにルート始まりなので、フォルダの中ではなくルートをドキュメントルートにします。`file://` で HTML を開くと、Service Worker と一部のパスが動きません。

```bash
python3 -m http.server 8000
```

ブラウザで <http://127.0.0.1:8000/> を開きます。別のポートでも構いません。Node が入っていれば `npx --yes serve -p 8000` でも同じです。`npx` はパッケージの取得が走ります。Python の標準サーバーで足ります。

見るところは次です。

- メニューの各カードが、その機種の先頭まで開く。
- 機種ページの先頭に、推測が無いときの文言が出る。G 数と当たりを入れると「数字のみ」が動く。
- 戻るリンクでメニューに戻る。
- 幅 390px 前後で、ボタンが画面外にはみ出さない。入力にフォーカスしてもページが極端に拡大しない（入力文字は 16px 以上）。

iPhone の Safari に、同じ Wi-Fi の `http://192.168.x.x:8000` でつなぐと、レイアウトは見られます。Service Worker は、localhost 以外の http では登録されないことが多いです。ホーム画面追加と、キャッシュ更新の確認は、公開後の <https://sugarsgith.github.io> で行います。

オフライン確認をするときは、一度 https の公開サイトをオンラインで開いてから機内モードにします。ローカルの http では、本番と同じキャッシュは入りません。

## 自動チェック

依存のインストールは不要です。リポジトリのルートで実行します。

```bash
node scripts/check-site.js
```

成功すると `OK` と件数を出して終了コード 0 です。失敗すると足りないパスか、構文エラーのファイルを出して終了コード 1 です。

見ている範囲は次だけです。

- メニュー `a.m` の相対リンクの先に `index.html` がある。
- `sw.js` と `taicho/sw.js` の `PRECACHE` のパスが、リポジトリ内にある。
- 各 HTML のインラインスクリプトと、その HTML が参照するローカル JS が、Node の構文解析を通る。
- メニューの設定推測機種（ハイエナと履歴以外）が、`history/index.html` の `MACHINE_TITLES` にある。
- SLOTSENSE のキャッシュ名が `slotsense-v` と番号、体調ログが `taicho-v` と番号である。

推測の確率が出典と一致するかは見ません。ブラウザの表示も見ません。機種を足したあとの目視は、上のローカルサーバーとスクリーンショットで行います。

## 公開

1. 作業ブランチでチェックを通し、利用者にプレビューを見せる。
2. `main` へマージする。このリポジトリでは、マージそのものが公開です。GitHub Actions のワークフローは無く、Pages が `main` をビルド済み状態で配信します。
3. 数分後に <https://sugarsgith.github.io> を再読み込みする。iPhone で古い画面が残るときは、その変更で `sw.js` の `slotsense-vN` を上げたかを見る。上げていれば、オンラインで開けば新しいワーカーが古い `slotsense-` キャッシュを消します。番号を上げ忘れていると、端末は古い HTML を持ち続けます。

`main` へ直接コミットして公開する運用にはしないでください。プレビューを挟みます。

体調ログだけを直したときは `taicho/sw.js` の `taicho-vN` を上げます。SLOTSENSE の `slotsense-vN` は、SLOTSENSE 側のファイルを変えたときだけ上げます。

## 機種を追加するチェックリスト

調査と利用者の OK が先です。OK の前にフォルダを作らないでください。ルールの詳細はルートの `AGENTS.md` です。

- [ ] 出典 URL、示唆 / ○以上 / 濃厚の語、不一致、調査中を文章で利用者に見せた
- [ ] 除外するか、重みにするか、記録だけにするかを利用者が選んだ
- [ ] `/短縮名/index.html` を、SAO2・防振り・戦国乙女5の型で作った（`SSTop.render`、保存キー `slotmemo:v1:短縮名`）
- [ ] ページ内に出典節がある。パチナビの数字は入っていない
- [ ] メニュー `index.html` にカードを足した
- [ ] `history/index.html` の `MACHINE_TITLES` に足した
- [ ] `sw.js` の `PRECACHE` に `/短縮名/` を足し、`slotsense-vN` を 1 つ上げた
- [ ] `docs/machines.md` に 1 件足した
- [ ] `node scripts/check-site.js` が成功した
- [ ] 幅 390px 前後のスクリーンショットを利用者に見せた
- [ ] 既存の `localStorage` キーを改名していない

ハイエナに状況を足すときも、出典の無い狙い目 G は空のまま「調査中」にします。炎炎ループ間の設定変更後が、その例です。

## 確率表を更新するチェックリスト

- [ ] 変える数字ごとに、ページの出典節にある URL と、いつの掲載かをメモした
- [ ] 1 つのサイトだけが違う値のときは、不一致として併記し、どちらを計算に使うかを利用者に確認した
- [ ] 空欄を、隣のセルや前作の数字で埋めていない（炎炎2のキャラ表で結合セルを補完した、のような例外は、合計 100% の検算と出典の書き方をページに残してある。同じことをするときもページに理由を書く）
- [ ] 「示唆」を「濃厚」に書き換えていない
- [ ] 保存済みメモのフィールド名を変えた場合は、読み込み時の移行を入れ、旧データで回数が残ることを確認した
- [ ] 表の載っている HTML を変えたので `slotsense-vN` を上げた
- [ ] `node scripts/check-site.js` が成功した
- [ ] 変更前後の推測（同じ入力での高設定域の百分率）を、スクリーンショットかコピー文で利用者に見せた

コピー文は各機種の「チャット用にコピー」です。確率の回帰テストは自動化していません。`window.sao2Test` などのフックはブラウザ上の手確認用で、このチェックスクリプトは呼びません。

# 体調ログで、コード上まだ触っていないもの

ここは未実装の要望と、読んだコードで本番とテストがずれている箇所です。実装済みの保護（壊れた JSON では保存を止める、候補の × は過去の記録を消さない、まとめは薬の影響を判定しない）は、作り直さずに維持します。新しい挙動は `taicho/AGENTS.md` のとおり、テストと利用者の OK のあとで足します。

`TODO` や `FIXME` のコメントは、2026-11-18 の `taicho/index.html` と `taicho/sw.js` にはありません。

## テストブランチにだけある表示

`fix/taicho-data-protection` の `f8cff53` は、睡眠のまとめの平均の文言、最長と最短の並び、グラフの軸、◆の色を変えています。`main` には入っていません。保存キーと `sw.js` は同じです。

この表示を本番へ出すかどうかは、利用者がテストで見て決めることです。出すときは `docs/taicho/maintenance.md` の手順で、両方のキャッシュ番号を上げます。テストブランチは、この表示変更のあと `CACHE` が `taicho-v1` のままです。

## 本番の見出しが「テスト版」

`main` の `<title>` は「体調ログ（テスト版）」、見出しの下は「テスト版 v3」です。データの版は 2 です。テスト用ビルドは `h1` とホーム画面の短い名前だけを「体調ログ テスト」に変え、`<title>` は変えません。

文言を変えるのは画面の変更なので、頼まれてからにします。変えるときは、ビルドスクリプトが探している `<h1>体調ログ</h1>` と `content="体調ログ"` が、まだ置換に一致するかを見ます。

## 呼ばれていない `chart`

`chart` は 14 日分の SVG を `#chart` へ書く関数です。HTML に `#chart` は無く、呼び出しもありません。まとめは `renderSum` です。消すかどうかは、画面の結果が変わらない整理であっても、頼まれてからにします。

## `data-theme`

CSS は `data-theme="light"` と `data-theme="dark"` を持っています。その属性を付ける JS はありません。暗色は `prefers-color-scheme` だけです。切り替えボタンを足すのは画面変更です。

## 診察用コピーに入っていない項目

「直近30日をコピー」にあるのは、日付、区分、気分、エネルギー、睡眠（覚醒分を引いた注記を含む）、できたこと、薬、メモです。副作用、中途覚醒の回数、「あまり眠らなくても元気だった」、薬の変更は入りません。足すときは、文面の見本を利用者に見せてからにします。

## 取り込みが更新しないもの

気づいた時は、同じ id があっても中身を置き換えません。薬の変更も同じ id は足しません。朝と夜だけ、`updatedAt` が新しいときに置き換わります。削除は、書き出し側に無いだけでは伝わりません。この規則を変えるときは、既存の id で記録が二重にならないことと、利用者が消した記録が復活しないことを、架空データで見せてからにします。

## 旧形式の `t` が数値のとき

`migrate` は `t` を `savedAt` にそのまま入れ、今の検証は文字列を要求します。数値の `t` は読み込みも取り込みも失敗し、起動時は保存を止めて生の文字列を書き出せます。リポジトリに v1 の実データは無く、数値で保存されていたかは分かりません。移行を広げるときは、今ある v2 を上書きしない形で、利用者の OK のあとです。

## 足していないもの

次はコードに無く、この文書の作成時にも頼まれていません。

- IndexedDB。今は `localStorage` だけです。
- アカウント、同期、解析、外部への送信。
- テストと本番で違う保存キー、違うキャッシュ名、違うスコープ。今の分離はオリジンだけです。`docs/taicho/structure.md` にリスクを書いてあります。キーを分ける変更は、本番の既存記録を読めなくなるので、移行と OK が先です。

# 体調ログのデータ

2026-11-18 の `main` の `taicho/index.html` を読んだものです。リポジトリに実記録はありません。下の JSON は形の見本で、架空です。

保存先は、そのオリジンの `localStorage` だけです。IndexedDB、Cookie、サーバは使っていません。Service Worker のキャッシュにあるのは HTML やアイコンで、記録ではありません。

## キー

| キー | 中身 |
| --- | --- |
| `taicho-log-v2` | 今の本体。オブジェクトの `v` は 2 |
| `taicho-log-v1` | 旧形式。v2 が無いときだけ読み、`migrate` して v2 へ書く。v1 のキー自体は消さない |
| `taicho-ov` | まとめの気分グラフ。`sep`（分けて表示）か `mix`（重ねて表示）。無いときは `sep` |

v2 がキーとして存在するときは、中身が壊れていても v1 へは戻りません。壊れた文字列は `rawRecovery` に残り、書き出しがそれを出します。

`taicho-ov` は本体のオブジェクトに入っていません。書き出しにも入りません。

画面の「テスト版 v3」は表示文です。データの版番号ではありません。

## v2 の形

`validate` が要求するのは次です。これ以外のフィールドが付いていても、検証は落としません。

```json
{
  "v": 2,
  "meds": ["薬A"],
  "changes": [
    {"id": "c-example", "date": "2026-11-01", "med": "薬A", "kind": "開始", "memo": ""}
  ],
  "items": []
}
```

- `v` は数値の 2 だけです。3 以上は今の検証では読めません。
- `meds` は薬の候補の名前の配列です。記録そのものではありません。
- `changes` は省略できます。読み込み後、メモリ上では空配列になります。
- `items` は記録の配列です。

薬の変更 1 件は `id`、`date`（`YYYY-MM-DD`）、`med`、`kind`、`memo` です。`kind` は「開始」「増量」「減量」「中止」だけです。画面が付ける id は `c-` に、ミリ秒とランダムな英数字 4 文字を足したものです。一覧の表示は日付の新しい方から 8 件で、保存されている件数とは違います。

## 記録のフィールド

| フィールド | 検証 | 画面での意味 |
| --- | --- | --- |
| `id` | 空でない文字列。配列内で一意 | 朝と夜は `日付-am` / `日付-pm`。気づいた時は `m-` で始まる |
| `date` | `YYYY-MM-DD` | カレンダーの日。未来日のボタンは押せない |
| `slot` | `am` / `pm` / `any` | 朝 / 夜 / 気づいた時 |
| `mood` | `null` か、-3 から 3 の整数 | 気分。未選択は `null` |
| `energy` | 同じ | エネルギー |
| `done` | 文字列の配列 | できたこと。ボタンは「入浴」「食事」「外出」 |
| `meds` | 文字列の配列 | その記録で選んだ薬 |
| `note` | 文字列 | ひとこと。空でもよい |
| `savedAt` | 日付として解釈できる文字列 | 最初の保存時刻。ISO 文字列 |
| `updatedAt` | 同じ | 最後の保存時刻 |
| `se` | 省略可。あるときは文字列の配列 | 副作用。ボタンは「眠気」「ふらつき」「吐き気」「食欲の変化」「口の渇き」「手の震え」「その他」 |
| `sleep` | 下の条件のときだけ必須 | 睡眠時間（時間）。小数第 1 位 |
| `sleepBed` | 覚醒時間があるときに計算へ使う | 寝た時刻 `HH:MM`。朝だけ |
| `sleepWake` | 同じ | 最後に目が覚めた時刻。朝だけ |
| `sleepAwakeMinutes` | 省略可。あるときは下の式と一致 | 途中で起きていた合計分。0 から 1440 の整数 |
| `lowneed` | 検証は型を見ない | 朝の「あまり眠らなくても元気だった」 |
| `wn` | 検証は値の範囲を見ない | 中途覚醒。なし 0、1 回、2 回、3 回以上 3。未選択は `null` |

朝と夜は、その日その枠で 1 件です。保存は上書きです。気づいた時は何件でも足せます。新しい id は `m-`、ISO 時刻、`-`、ランダム 4 文字です。

朝を保存するとき、睡眠の欄は常に付きます。寝た時刻と覚めた時刻の初期表示は `23:00` と `07:00` です。利用者が触らなくても、朝の保存はこの初期値で時間を計算します。

時間の計算は次です。

- 覚めた時刻が寝た時刻以下なら、24 時間を足す（日をまたぐ）。
- 覚醒分が空欄なら、その長さを時間にし、`sleepAwakeMinutes` は付けない。
- 覚醒分があるなら、長さからその分を引く。引いた結果が負になる入力は保存しない。時刻が無いのに分だけある入力も保存しない。
- 時間への丸めは、分を 6 で割り、整数へ丸め、10 で割る。6 分が 0.1 時間です。覚醒 30 分を引いた 450 分は 7.5 です。
- `sleepAwakeMinutes` がある記録は、`slot` が `am` で、`sleep` がこの丸めと一致しないと検証が失敗します。

気分とエネルギーが両方 `null` の保存は、画面が断り、記録を足しません。

候補の「×」は `meds` から名前を消すだけです。過去の記録の `meds` には残します。画面にもその文があります。

## 旧形式（v1）

リポジトリに v1 の実例はありません。`migrate` が読んでいる形だけが仕様です。

```json
{
  "meds": ["薬A"],
  "entries": [
    {
      "t": "2026-11-01T22:00:00.000Z",
      "mode": "wake",
      "mood": 0,
      "energy": 0,
      "sleep": 7,
      "lowneed": false,
      "done": [],
      "meds": [],
      "note": ""
    }
  ]
}
```

- `mode` が `wake` なら朝、`bath` なら夜、それ以外は気づいた時。
- 日付は `t` を、移行を実行した端末のローカル日付にした `YYYY-MM-DD` です。
- 朝と夜の id は `日付-am` / `日付-pm`。同じ id が複数あるときは、`t` の `<` 比較で大きい方を残します。画面が書く時刻は `toISOString()` なので、この比較は時刻の前後と一致します。
- 気づいた時の id は `m-` と `t` を連結したものです。
- `savedAt` と `updatedAt` は `t` をそのまま入れます。今の検証は、それらが文字列で、日付として解釈できることを要求します。`t` が数値の旧データは、移行のあと検証で失敗します。その場合の起動は保存を止め、書き出しに元の文字列を出します。同じ文字列の取り込みも失敗します。v1 の実物が数値かどうかは、リポジトリからは分かりません。
- 移行結果に `changes` はありません。副作用、寝た時刻、覚醒分、`wn` も移しません。`sleep` は `e.sleep` が無ければ `null` です。

## 書き出す文字列

「書き出す」は、読み込みに成功しているとき `JSON.stringify(S)` です。保存済みの生文字列そのものではありません。`changes` を持たない v2 でも、画面が空配列を足したあとなら、書き出しには `"changes":[]` が入ります。

読み込みに失敗しているときは、`localStorage` から読んだ生の文字列を出します。それが v1 でも、壊れた JSON でも、画面は直しません。生文字列が無いときは「元データを読み出せません」と出します。

クリップボードへコピーできなければ、テキスト欄の文字列を自分でコピーする案内になります。

診察用の「直近30日をコピー」は別の文です。記録がある日付を新しい方から 30 日分、タブ区切りではなく ` / ` 区切りのテキストにします。列は日付、区分と保存時刻、気分、エネルギー、睡眠、できたこと、薬、メモです。副作用、中途覚醒の回数、「あまり眠らなくても元気だった」、薬の変更は入りません。

## 取り込む

テキスト欄の JSON を解析します。`entries` があれば先に `migrate` します。そのあと v2 として検証し、今の画面上のデータをコピーしたものへ足します。検証か保存に失敗したら、今の `S` は差し替えません。

- 薬の候補は、無い名前だけ足す。候補から消すことはしない。
- 薬の変更は、同じ `id` が無いときだけ足す。同じ id の中身は更新しない。
- 記録は、同じ `id` が無ければ足す。
- 朝と夜は、同じ id で、取り込んだ側の `updatedAt` が `>` で今の値より大きいときだけ置き換える。画面の時刻は `toISOString()` です。
- 気づいた時は、同じ id があっても置き換えない。id が新しいときだけ足す。
- どちらかにしか無い記録は、取り込みでは消えない。

成功の文は「追加○件、更新○件」です。追加は新しい記録と新しい薬の変更、更新は置き換えた朝と夜です。薬の候補の追加はこの件数に入りません。

読み込みを止めているあいだは、書き出しとテキスト欄以外の操作を無効にします。取り込みボタンも無効です。

## 保存に失敗したとき

`localStorage` へ書けなかったときは、そのキーを書き換えません。画面のメッセージは「保存できませんでした。入力は残しています。書き出しで控えを取ってください。」です。

保存・削除・薬の候補・薬の変更は、メモリ上の `S` を先に変えてから書きます。書き込みに失敗しても、そのメモリ上の変更は戻しません。再読み込みすると、最後に書けた内容に戻ります。気づいた時の削除と、薬の変更の削除は、失敗しても画面をそのメモリの状態で描き直します。

この失敗時の動きを、成功したように見せる変更はしないでください。

## 新しい端末へ移す

記録は端末の中だけなので、機種変更は書き出し文字列を自分で移します。

1. 古い端末で、本番のホーム画面か <https://sugarsgith.github.io/taicho/> を開く。テスト環境のアイコンではないこと（見出しが「体調ログ テスト」の方は使わない）。
2. 「書き出す」を押す。出た文字列を、利用者自身が保管する場所へコピーする。リポジトリやチャットに貼らない。
3. 新しい端末の Safari で同じ本番 URL を開き、必要ならホーム画面へ追加する。一度オンラインで開き、Service Worker を入れる。
4. 新しい端末の記録が空であることを見る。既に架空のデータがあると、次の手順はマージになり、消えない。
5. 文字列をテキスト欄へ貼り、「取り込む」を押す。追加件数を見る。
6. カレンダーと、移したい日の朝・夜・気づいた時を開いて残っていることを見る。
7. 気分グラフの分けて / 重ねては `taicho-ov` なので移りません。新しい端末では最初「分けて表示」です。

古い端末の v1 キーは、移行済みでも残っていることがあります。新しい端末にできるのは、取り込みで書いた v2 です。

テスト環境と本番のあいだでは、この手順を使わないでください。形式は同じなので取り込みは成功し、記録がコピーされます。

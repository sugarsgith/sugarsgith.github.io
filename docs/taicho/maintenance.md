# 体調ログの確認と公開

アプリの HTML は、頼まれた修正以外では変えません。公開の本番は GitHub Pages が `main` を <https://sugarsgith.github.io/taicho/> で配信します。テストを先に見て、利用者の OK のあとだけ `main` へ入れます。

## ローカルで開く

パスが `/taicho/` で始まるので、リポジトリのルートをドキュメントルートにします。`file://` では Service Worker が登録されません。

```bash
python3 -m http.server 8000
```

ブラウザで <http://127.0.0.1:8000/taicho/> を開きます。これは本番のファイルです。テストブランチの表示を見るときは、そのブランチをチェックアウトしてから同じように開きます。`127.0.0.1` と `sugarsgith.github.io` は別オリジンなので、公開サイトの記録は読みません。同じホストとポートでブランチだけ切り替えて開くと、保存キーが同じなので記録は混ざります。ローカルの確認は空のプロフィールか、架空データだけで行います。

ローカルで見るところは次です。

- 記録を 1 件保存し、再読み込みで残る。
- 朝の睡眠で、覚醒分の空欄と 0 分が違うこと。範囲外は保存されないこと。
- まとめの期間と、分けて表示 / 重ねて表示。
- 書き出した文字列を、一度消したあと取り込みで戻せるか（架空データだけ。本番からコピーした文字列は使わない）。
- 幅 390px 前後で、ボタンが画面の外に出ない。入力は 16px 以上。

iPhone のホーム画面追加とオフラインは、localhost では本番と同じになりません。テスト用ホストか、公開後の本番 URL で見ます。オフラインの確認は、一度オンラインで開いてから機内モードにします。

テスト用の生成物だけを見るときは、テストブランチで次を実行します。出力は `taicho-preview-dist/` です。

```bash
node taicho/build-preview.cjs
python3 -m http.server -d taicho-preview-dist 8000
```

開く URL は <http://127.0.0.1:8000/taicho/> です。見出しが「体調ログ テスト」になります。このディレクトリを本番のリポジトリへコミットしないでください。

## 自動チェック

依存のインストールは不要です。リポジトリのルートで実行します。

```bash
node scripts/check-site.js
```

体調ログで見ているものは次です。

- `taicho/index.html` のインライン JS が構文として解析できる。
- `taicho/manifest.webmanifest` が JSON で、`scope` と `start_url` が `/taicho/`、アイコンの実体がある。
- `taicho/sw.js` のキャッシュ名が `taicho-v` と番号で、事前キャッシュが `/taicho/` 以下にあり、実体がある。
- ルートのメニューが体調ログを指していない。SLOTSENSE の事前キャッシュに `/taicho` が無い。
- ブランチ `fix/taicho-data-protection`（無ければ同名のローカルブランチ）の `index.html`、`sw.js`、マニフェスト、`build-preview.cjs` が同じ条件を満たす。

このブランチを `git fetch` していないクローンでは、最後の項目で失敗します。記録の計算や、取り込みの件数が正しいことは見ません。

## テストで直してから本番へ出す

アプリの変更は `fix/taicho-data-protection` で行います。`main` の `taicho/` へ先に入れません。大きい見た目、文言、睡眠の計算、保存形式は、テストブランチへ入れる前に候補を見せ、利用者に選んでもらいます。

1. テストブランチでアプリを直す。`build-preview.cjs` の、表示名を「体調ログ テスト」にする処理は残す。保存キーをこのスクリプトで書き換えないままにしない、という方針を変えるときは、利用者の OK と、移行と、この文書の更新が先です。今のスクリプトはキーを分けていません。リスクは `docs/taicho/structure.md` に書いてあります。
2. HTML、CSS、JS、アイコン、マニフェスト、`sw.js` のどれかを変えたら、テストブランチの `taicho/sw.js` の `CACHE` を 1 つ上げる。`taicho-v1` なら `taicho-v2`。接頭辞 `taicho-` は変えない。2026-11-18 時点で、テストブランチは睡眠のまとめ表示を変えたあとも `taicho-v1` のままです。次にそのブランチを触るときは、その上げ忘れも一緒に上げます。
3. テストブランチを push する。Cloudflare Pages のコマンドと出力先は、`build-preview.cjs` のコメントにあるとおりです。ホスト名と、どのブランチを追うかはリポジトリに無いので、利用者に開いているテストの URL を確認します。
4. テストでは架空データだけを入れる。本番の書き出しは貼らない。
5. iPhone の Safari で、記録、保存、再読み込み、まとめ、書き出し、ホーム画面からの起動、オフラインを見る。幅 390px 前後の画面を利用者に見せる。
6. 利用者の OK が出てから本番へ出す。OK の前に `main` へマージしない。

## 本番へ出す

これまでの出し方は、PR #1 と PR #2 です。本文に「Cloudflareテスト用ビルド設定は含みません」とあり、`release/taicho-data-protection` と `release/taicho-awake-minutes` から `main` へ入っています。`build-preview.cjs` は `main` に入っていません。

1. `main` から `release/taicho-...` のようなブランチを切る。
2. テストで OK になったアプリの変更だけを載せる。`build-preview.cjs`、出力ディレクトリ、テスト用の `.gitignore` は載せない。見出しを「体調ログ テスト」にした生成物も載せない。
3. 本番の `taicho/sw.js` を上げる。テストと本番はオリジンが違うので、キャッシュの実体は共有されません。番号はそれぞれのファイルで上げます。テストで上げた `sw.js` を本番へ持ってくるなら、その番号が本番の上げです。テストが番号を上げないまま HTML だけ新しいときは、本番へ入れる時点で本番の番号を上げます。両方とも接頭辞は `taicho-` のままです。
4. SLOTSENSE の `slotsense-vN` は上げない。機種ページやルートの `sw.js` は変えない。
5. `node scripts/check-site.js` を通す。
6. PR の本文に、テストで見たことと、保存キーを変えていないことを書く。利用者が見てから `main` へマージする。マージが本番の公開です。Actions のビルドはありません。
7. 数分後に <https://sugarsgith.github.io/taicho/> をオンラインで開く。番号を上げていれば、新しいワーカーが古い `taicho-` キャッシュを消します。

`main` へ直接コミットして公開しないでください。

## 保存形式を変えるとき

テストの手順に加え、`docs/taicho/data.md` の移行規則に従います。

- 新しいフィールドは足すだけにし、古い書き出しが今の検証を通るようにする。
- `v` を上げるときは、旧 v2 と、`entries` を持つ旧形式の両方を読む移行を足す。移行の前に上書きしない。
- 利用者には、変える前の書き出しを自分の保管場所へ取る手順を見せる。リポジトリへは取り込まない。
- 架空データで、旧形式の取り込み、同じ文字列の再取り込み、壊れた JSON で保存が止まることを見てから OK をもらう。

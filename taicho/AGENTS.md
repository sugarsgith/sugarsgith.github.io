# AGENTS.md（体調ログ）

体調ログをあとから直す AI（Codex など）向けのルールです。スロットセンス（SLOTSENSE）とは別の個人用 PWA です。公開サイトは <https://sugarsgith.github.io/taicho/> です。iPhone の Safari で、ホーム画面に追加して使います。

画面の文言、保存した記録の意味、睡眠時間の計算を、頼まれていない変更で動かさないでください。診断や判定を足さないでください。ページ自身が「診断や判定はしません。記録は医師に相談する時の材料です」と書いています。

詳しい対応表は `docs/taicho/` です。

| 文書 | 内容 |
| --- | --- |
| `docs/taicho/structure.md` | ファイル、Service Worker、本番とテスト環境 |
| `docs/taicho/data.md` | 保存キー、記録のフィールド、書き出し文字列、機種変更 |
| `docs/taicho/maintenance.md` | ローカル確認、テストから本番へ出す手順、公開 |
| `docs/taicho/backlog.md` | コード上の未使用と、まだ本番に無い変更 |

## 記録を消さない

記録は利用者の端末の中だけにあります。キー名を変えると、その端末の画面から記録が消えます。

- キーは `taicho-log-v2`、旧形式の `taicho-log-v1`、表示切替の `taicho-ov` です。名前を変えない。IndexedDB は使っていません。
- フィールドを足すときは、同じオブジェクトに足す。読み込みは、今の形を検証してから使う。知らないフィールドを、保存し直すときに捨てない。
- 意味や型を変えるときは、`v` を上げ、読み込み時の移行を足す。移行の前に、今の文字列を退避できる状態を残す。移したあと、利用者が入れた記録・薬の候補・薬の変更が残っていること。
- 古い書き出し文字列を、今の「取り込む」で読めるように保つ。`entries` を持つ旧形式は `migrate` が v2 にします。
- JSON が壊れていたら保存と取り込みを止める。`loadBlocked` と、書き出しで元の文字列を出す動きを弱めない。失敗した保存で、作業中の入力を消さない。
- 形式を変える作業の前に、書き出し手順を文書で示し、利用者の OK をもらう。

保存の詳細、マージの規則、新しい端末への移し方は `docs/taicho/data.md` です。

## 端末の外へ出さない

解析、外部への送信、サーバ、アカウント同期を足さない。利用者が明示して頼んだときだけ、その範囲で足す。

ページ内の JS は `localStorage` とクリップボード以外へデータを出しません。Service Worker は、制御しているページからの同一オリジンの GET をネットワーク優先で扱います。今の画面が参照するのは `/taicho/` 以下のマニフェスト、アイコン、`sw.js` です。

書き出した文字列には体調と薬の名前が入ります。それをリポジトリ、ログ、チャットの貼り付け例に写さない。文書の例は架空の形だけにする。

URL は公開です。データを持っているのは、その端末のブラウザだけです。ページの注記「データはこの端末のブラウザ内に保存されます」を消さない。

## Service Worker

`taicho/sw.js` はネットワーク優先です。オフラインのときだけキャッシュを返します。キャッシュ名は `taicho-vN` です。起動時に、`taicho-` で始まる古いキャッシュを消します。

HTML・CSS・JS・アイコン・マニフェストのどれかを変えたら、変えた方の `CACHE` を 1 つ上げます。接頭辞 `taicho-` は変えない。変えると、古いキャッシュを消す処理が一致しません。

本番とテストはオリジンが違います。番号はそれぞれの `sw.js` で上げます。上げ忘れは `docs/taicho/maintenance.md` の手順にあります。

SLOTSENSE の `sw.js`（`slotsense-vN`）は、体調ログの変更では上げません。逆も同じです。`/taicho/sw.js` のスコープは `/taicho/` のままにします。

## スロットセンスと混ぜない

- ルートのメニュー、`history/index.html` の `MACHINE_TITLES`、SLOTSENSE の `PRECACHE` に体調ログを足さない。
- マニフェスト、アイコン、Service Worker、保存キーを SLOTSENSE と共有しない。
- `topbar.js` を体調ログから読まない。体調ログの JS を機種ページから読まない。
- 引き継ぎの Markdown は `docs/taicho/` に置く。`/taicho/` の下に説明用の HTML を増やすと、スコープ `/taicho/` の Service Worker がそれを取得対象にします。この `taicho/AGENTS.md` は、エージェントがアプリの隣で読むための 1 枚です。アプリの画面からはリンクしていません。

## テストを先に、本番は OK のあと

テスト環境はブランチ `fix/taicho-data-protection` です。ビルドは `taicho/build-preview.cjs`（このブランチにだけある）です。`main` 上の `taicho/` が本番で、GitHub Pages が <https://sugarsgith.github.io/taicho/> を配信します。

- アプリの変更は、まずテストブランチに入れる。利用者がテスト環境で見る前に、`main` へ入れない。
- 見た目、文言、計算、保存形式の大きい変更は、テストに出す前に候補を見せて OK をもらう。
- 本番へ出すのは、利用者の OK のあとだけです。手順、両方のキャッシュ番号、分離の抜けは `docs/taicho/maintenance.md` と `docs/taicho/structure.md` に書いてあります。
- テスト用の出力を、本番と同じオリジンへ置かない。保存キーもキャッシュ名も、ソース上は本番と同じです。分かれているのは配信元のオリジンだけです。

## 画面（iPhone の Safari）

ホーム画面追加（`apple-mobile-web-app-capable`、アイコン、マニフェスト、`start_url` `/taicho/`）を外さない。横幅の上限は 520px です。入力の文字は 16px 以上、暗色は `prefers-color-scheme` に任せる。

公開の前に、幅 390px 前後で主な操作（記録、保存、まとめ、書き出し、メニューではなくこのアプリ内のタブ）の画面を利用者に見せる。OK の前に `main` へマージしない。

## チェック

リポジトリのルートで次を実行します。依存パッケージはありません。

```bash
node scripts/check-site.js
```

体調ログについては、本番のインライン JS、マニフェスト、Service Worker の事前キャッシュ、メニューからリンクしていないこと、テストブランチの JS とマニフェストと `build-preview.cjs` の構文を見ます。記録の中身が正しいことの証明にはなりません。テストブランチを取得していないクローンでは、その項目で失敗します。
